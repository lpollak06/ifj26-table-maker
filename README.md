# IFJ26 Table Maker

Interactive helper for designing the LL(1) table and the precedence table of the IFJ26 compiler.
Not part of the compiler itself.

Live (tailnet only): https://t3-exec.tailedbcdc.ts.net:4310/

## Stack

- TanStack Start + TanStack Router (React 19, SSR, server functions), Vite, Tailwind CSS v4
- SQLite through Node's built-in `node:sqlite` (Node ≥ 22.13), no native addons
- UI components from [React Bits](https://www.reactbits.dev/) (TS + Tailwind variants), vendored unmodified in
  `src/components/reactbits/`: GooeyNav, SpotlightCard, StarBorder, ShinyText, ClickSpark, CountUp, SwipeToast, Aurora

## Layout

| Path | Purpose |
| --- | --- |
| `src/lib/grammar.ts` | Grammar parser, Empty/First/Follow/Predict, LL table, LL simulation |
| `src/lib/precedence.ts` | Precedence table helpers, checks, precedence simulation |
| `src/lib/exports.ts` | Markdown / CSV / LaTeX / C exports |
| `src/server/db.server.ts` | SQLite connection + migrations (`PRAGMA user_version`) |
| `src/server/projects.server.ts` | Projects and snapshots (history) |
| `src/server/projects.functions.ts` | Server functions called by the UI |
| `src/routes/` | `/` project list, `/p/$projectId?tab=ll\|prec\|export\|history` editor |
| `deploy/` | systemd unit and deploy script |

Each project is one JSON document in the `projects` table. Saves are debounced and use a revision
number, so two tabs or two people editing the same project get a conflict prompt instead of silently
overwriting each other. An automatic backup is kept at most every 20 minutes (last 30), and named
versions can be saved and restored on the History tab. Project JSON files from the original
single-file `tools/table-maker.html` can be imported.

## Development

```sh
npm install
npm run dev        # http://localhost:3000, database in ./data/table-maker.db
npm run typecheck
npm run build      # Node server in .output/
```

`TABLE_MAKER_DB` overrides the database path, `HOST` / `PORT` the listen address.

## Deployment

```sh
tools/table-maker/deploy/deploy.sh            # default ssh host: t3-exec
```

The script syncs the sources to `~/build/table-maker` on the VM, runs `npm ci`, typecheck and build,
installs the output to `/opt/table-maker` and restarts `table-maker.service`. The service listens on
`127.0.0.1:4310` only and runs as a sandboxed dynamic user. The database lives in
`/var/lib/private/table-maker/table-maker.db` (reached through the `/var/lib/table-maker` symlink).
`tailscale serve` publishes it over HTTPS to the tailnet on port 4310. It's not reachable from the LAN
or the internet.

Useful commands on the VM:

```sh
systemctl status table-maker
journalctl -u table-maker -f
tailscale serve status
```
